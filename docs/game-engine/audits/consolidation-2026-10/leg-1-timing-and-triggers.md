# Leg 1 — Timing and triggers

Basis: local rules file `docs/rules/rule_comprehensive.md` (v1.2.0). The proposal cites v1.2.1 (Aug 28, 2026), which is not in the repo; findings below cite v1.2.0 text only. FAQ rulings exist in the repo only as code comments and one summary doc; the FAQ text itself is not in the repo.

## Verdict

The five headline claims in the §7 table (A→X→C, A→B→C, End Phase waves, Life Trigger interrupt, ordinary triggers wait for damage) match the rule text, but §8-6-1-1 only says C "can" resolve after B, so the proposal states as mandatory what the rule permits. The proposal omits several rule-required behaviors: battle-step zone checks (§7-1-1-4, §7-1-2-3, §7-1-3-3), the infinite-loop rule (§11-1), once-per-turn use during cost payment (§10-2-13-5), and the rule that a moved source cannot activate an auto effect (§8-1-3-1-3), which the OPT-937 source-snapshot plan could violate. Current code contradicts the rules in at least five places (`pipeline.ts:352`, `coordinator.ts:315`, `phases.ts:143-146`, `engine-limits.ts:89`, `battle.ts:1148-1160`), and Phase 0 and Phase 2 fixtures should pin these before any executor merge.

## FAQ rulings found in source relevant to timing

The requested grep matched five comments. Items 1-6 below include those five plus one doc summary (item 4). The FAQ texts themselves are not in the repo.

1. **OPT-259 (self-damage, Life Trigger window).** `workers/game/src/__tests__/opt-259-life-trigger-damage-only.test.ts:17-20`: "SELF_TAKE_DAMAGE does NOT open a Trigger window — the FAQ gates the window on 'opponent deals damage'." Phase 1 must encode this. The rule text 10-1-5-1 has no opponent qualifier, so the FAQ is the only source of this limit.
2. **OP16-107 Jesus Burgess (unpayable Trigger cost).** `workers/game/src/engine/battle.ts:1340-1352` (`canOfferTrigger`): a Trigger whose activation cost cannot be paid is not offered; "Applies to every costed trigger." Also `workers/game/src/__tests__/opt-413-op16-faq-fixes.test.ts:8` (finding 5). The proposal does not mention this gate.
3. **OP09-081 Marshall.D.Teach (trigger negation).** `workers/game/src/engine/triggers.ts:306-318`: negation comes from two sources (`NEGATE_TRIGGER_TYPE` prohibitions, and `TRIGGER_TYPE_NEGATION` rule modifications), and the prohibition is controller-scoped and prospective. Relevant to 8-1-3-1-3 (row 24): a queued trigger's eligibility must be rechecked at activation.
4. **Bandai FAQ on Event activation classes.** `docs/game-engine/02-TRIGGERS.md:307-313`: for "when your opponent activates an Event," classes 1 and 2 count, and class 3 (`EVENT_TRIGGER_RESOLVED`, a Life Trigger resolution) does NOT count. Relevant to row 27 (event-activation debt in Phase 1).
5. **"After-trigger" ordering (unverified).** `workers/game/src/engine/triggers.ts:751-753` says `CARD_REMOVED_FROM_LIFE` was split out because the old alias "collapsed the FAQ's 'after-trigger' ordering." The FAQ text is not in the repo, so the ordering claim cannot be checked here. Phase 1 or 2 fixture pending the FAQ text.
6. **Battle-end performed-action record (OP12-020 Zoro / OP16-080 Teach redirect).** `opt-413-op16-faq-fixes.test.ts:9-10` (finding 6): "ATTACKED performed-actions record attacker + final target at battle end." Relevant to row 20 (battle end ordering after a redirect). Phase 2 fixture.

Related card text (not FAQ): OP15-022 Brook, `docs/cards/OP-15.md:158`, "You lose at the end of the turn in which your deck becomes 0 cards." Governs row 16 under 1-3-1.
