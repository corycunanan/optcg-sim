## Engine and replacement observations

It checks `isRemovalProhibited` with action `TRASH`, cause `EFFECT`, then trashes the Character. It contains no `processBatchReplacements` call. By contrast, the same file's `executeKO` (lines 70-120), `executeReturnToHand` (150-190), and `executeReturnToDeck` (300-360) call `processBatchReplacements` for their respective removal event sets. `workers/game/src/engine/replacements.ts:264-320` checks event equality, target filter, cause filter and condition; removal/leave replacement matching is scoped to field zones. Therefore these field-trash actions do not enter the replacement path used by KO/return actions and must not be treated as K.O. or those ordinary removal-replacement events.

## Replacement eligibility edges

The field-trash action itself is not K.O.; only removal-effect replacements should match when printed timing/cause/type conditions fit. `docs/cards/OP-11.md` OP11-001 Koby protects a qualifying own Navy Character “would be removed from the field by your opponent's effect”; opponent-driven field trash is a plausible match. `docs/cards/OP-17.md` OP17-043 Ganzui applies whenever it “would be removed from the field” (no opponent-effect restriction) and pays by trashing 2 from hand. These are replacement eligibility, not additional `TRASH_CARD` opponent-target rows. `docs/cards/OP-15.md` OP15-094 Zoro substitutes itself when another own Straw Hat would be removed by opponent effect; OP08-045 Thatch and ST30-009 LittleOars Jr. similarly have self-trash replacements. Ensure a replacement action's own `TRASH_CARD SELF` does not recursively offer the same replacement or treat the original target as K.O. Conversely, `CANNOT_BE_KO` alone must not block these trash actions; the pinned handler explicitly checks removal/leave prohibition, while treating trash as not K.O. Non-K.O. replacement candidates such as Ganzui/Koby are the key distinction from K.O.-only substitutions (e.g. OP09-012 Monster in `docs/cards/OP-09.md`).
