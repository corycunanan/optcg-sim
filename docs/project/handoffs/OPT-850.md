# OPT-850 — nested Event Main activation

Implementation handoff; merge readiness and exact tested head are recorded in the
PR body. Branch: `corymcunanan/opt-850-resolve-the-selected-event-main-effect-for-authored-hand`.
Issue: https://linear.app/optcg-sim/issue/OPT-850

`ACTIVATE_EVENT_FROM_HAND` now resolves the selected Event's Main using normal
resolver costs and resumable frames. The selected Event moves to trash with fresh
identity; trash Main activation retains its existing identity. Both use a separate
completion frame so partial publication cannot release the activation notification
before Main finishes. Parent prefixes, remaining actions, result refs and source
identity are retained underneath the nested Event. The completion frame is consumed
once, including after optional decline or inability to pay an internal Main cost.
This distinguishes Event-card activation from successfully activating its effect.

Read first: `effect-resolver/event-activation.ts`, the hand/trash handlers in
`effect-resolver/actions/play.ts`, `resume/target.ts`, `resume-core.ts`, and
`opt-850-nested-event-activation.test.ts`. The optional persisted
`eventActivationCompletion` field is accepted only on an interrupted frame and
only for the two existing activation notification event shapes. It is separate
from `accumulatedEvents`, which contain already committed work. Visible player and
spectator states strip the effect stack. No authored schema, generated registry,
normal play/counter path, Life Trigger path, or production UI changed.

## Follow-ups and constraints

The pre-existing trash-activation watcher classification conflicts with the Reiju
FAQ (`docs/FAQs/qa_eb03.md`: Page One must not activate when only Event Main is
activated from trash). This change preserves those existing subscriptions; its
new trash tests assert Main execution/notification, not printed-correct Page One
behavior. [OPT-854](https://linear.app/optcg-sim/issue/OPT-854) tracks this classification follow-up.
The executable expected-failure probe is preserved as
`workers/game/src/__tests__/opt-854-trash-activation-known-gap.test.ts.txt`.
Independent review ran it against base `549bfb1` and implementation `ec4da66`: both
produce the same single FAQ assertion failure after completing Page One's erroneous
hand-bottom prompt. The fixture pays printed Reiju cost 4 plus DON−1 and moves an
existing cost-area DON to Page One; it does not fabricate attached resources.

No successor ticket is required by this implementation. Independent ordering and
persistence review, latest-main integration and all readiness gates remain required
before the coordinating agent may merge. Implementer does not merge or write Linear.
