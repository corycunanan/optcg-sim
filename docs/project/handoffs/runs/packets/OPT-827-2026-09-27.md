## Failure classes to prove or rule out
1. **Identity after zone change.** The milled card gets a fresh instance id in trash (zone-transition contract, rule 3-1-6). The ref must resolve to the card actually moved (store the new id and/or a snapshot of the needed properties), and must not match any unrelated board/trash card.
2. **Printed vs effective cost.** In trash there are no modifiers; decide and cite what "has a cost of 6 or more" reads (printed cost of the trashed card). A card without a cost (Leader? DON!!? none can be in a deck except Characters/Events/Stages — verify) must be handled deterministically.
3. **Empty deck.** Mill 0 cards → the ref is empty → the gate is false → no +5000; no crash. (Deck-out defeat timing mid-resolution is a known separate defect, OPT-862 — do not change defeat processing; if your empty-deck test reaches it, assert only what this ticket owns and note it.)
4. **Persisted continuation.** "Up to 1 of your Leader or Character cards" prompts a selection; the ref (and snapshot) must survive serialization of the pending prompt and resume, exactly once. Test via the real pipeline with a JSON round-trip of state between prompt and response if that is how existing persistence tests do it.
5. **Shared blast radius.** Any change to MILL action result recording or to REVEALED_CARD_PROPERTY evaluation touches other cards — run a consumer inventory through the schema registry (not grep alone) and show existing users are unaffected.
