# OPT-907 — document player-scoped trigger patterns

Small documentation-only change based on main `1dd5f5b9f42d262bb764ce0c3a3aab91b7939a06`, isolated clone. No runtime, schema, generated registry, or test changes.

## Acceptance and row audit

Reviewed every row in both README trigger tables. Rows without player wording are generic patterns and receive no new controller restriction. The following covers every you/your/opponent-worded row, plus the attacker-specific damage row:

| Row | Decision and evidence |
| --- | --- |
| Keyword: On Your Opponent's Attack | Unchanged. `matchesKeywordTrigger` explicitly excludes the source controller's active turn. |
| Keyword: End of Your Turn | Unchanged. Matcher requires `event.playerIndex === sourceCard.controller`. |
| Keyword: End of Your Opponent's Turn | Unchanged. Matcher requires different event/source controllers. |
| Keyword: Start of Your Turn | Add `turn_restriction: "YOUR_TURN"`. `START_OF_TURN` maps to `TURN_STARTED` without an inherent controller check; the existing generic keyword turn restriction compares active player with source controller. `phases.ts` sets the new active player before emitting `TURN_STARTED`. |
| Opponent's Character K.O.'d | Unchanged. Current main's OPT-906 matcher compares removed card `sourceController` (fallback `event.playerIndex`) against watcher controller. |
| Opponent's Character trashed | Unchanged. Same inherent OPT-906 controller check. |
| You/your opponent activates an Event | Split into SELF and OPPONENT rows. Generic `matchesEventFilter` compares `event.playerIndex`; no inherent scope. Precedents: OP01-062 Crocodile (SELF), OP01-004 Usopp (OPPONENT). Retain card-activation/rule 8-5-4 wording. |
| You play a Character | Add `filter: { controller: "SELF" }`. `CHARACTER_PLAYED` maps to `CARD_PLAYED`; no inherent controller handling. OP02-026 Sanji uses SELF. |
| Card trashed from your hand by an effect | Unchanged. Existing SELF plus BY_EFFECT filters explicitly scope this row; matcher also checks effect hand-trash eligibility. |
| You draw outside Draw Phase | Unchanged. Existing SELF filter supplies player scope (OPT-875 correction). |
| You take damage | Unchanged tracked limitation: `DAMAGE_TAKEN` maps to `DAMAGE_DEALT`; receiver semantics are a separate live bug, OPT-887. This is not endorsed as a corrected pattern. |
| Opponent activates Blocker | Add OPPONENT filter. `BLOCKER_ACTIVATED` maps to `BLOCK_DECLARED`; `battle.ts` emits defender as `playerIndex`. OP06-048 Zeff has the explicit OPPONENT filter. |
| This Leader's/Character's attack deals damage | Unchanged. `matchesAttackDamage` checks dealing controller, first/nonlethal attack damage, and `filter.attacker: SELF` against attacker identity. Effect-damage scope remains OPT-892. |
| You deal damage to your opponent's Life | Unchanged. `matchesAttackDamage` inherently requires event/source controller equality; effect-damage eligibility remains the separate OPT-892 rules decision. |
| Custom event: At end of your turn | Unchanged here; invalid custom form owned by OPT-878 / PR #740. Its fix is independent of this PR; no duplicated edit. |

Runtime evidence: `workers/game/src/engine/triggers.ts` (`matchesKeywordTrigger`, `matchesCustomTrigger`, `matchesEventFilter`, `matchesAttackDamage`, event maps), `battle.ts` BLOCK_DECLARED emission, and `phases.ts` TURN_STARTED emission. Authored precedents in `schemas/op01.ts`, `op02.ts`, and `op06.ts`. The start-turn documentation correction follows existing runtime restriction semantics; it does not claim an already-correct authored precedent.
